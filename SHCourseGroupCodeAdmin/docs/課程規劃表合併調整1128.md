# 課程規劃表合併調整記錄 - 1128

## 修改日期
2025年11月28日

## 修改檔案
`UIForm/frmGPlanConfig108_MergeSubject.cs`

## 問題說明
原本的新增筆數 `AddSubejctCount` 使用「RowIndex 分組」計算，導致以下問題：
1. `AddSubejctCount` 初始值為 0 時：第一筆永遠不算 → 結果少 1 筆
2. 初始值改為 1 時：即使無新增資料也會顯示「新增 1 筆」
3. 同 RowIndex 的多筆科目只會算成 1 筆
4. 正確筆數應為「實際新增的科目數量」= `AddSubjectList.Count`

**原因：** RowIndex 不應用來做筆數計算，只應用於排序。

## 修改內容

### 1. 移除錯誤的 AddSubejctCount 計算方式
- **位置：** 第 147-151 行
- **修改前：**
  ```csharp
  if (strRowIdx != NewElm.Element("Grouping").Attribute("RowIndex").Value)
  {
      LastRowIdx++;
      strRowIdx = NewElm.Element("Grouping").Attribute("RowIndex").Value;
      AddSubejctCount++;  // ❌ 移除此行
  }
  ```
- **修改後：**
  ```csharp
  else if (strRowIdx != NewElm.Element("Grouping").Attribute("RowIndex").Value)
  {
      LastRowIdx++;
      strRowIdx = NewElm.Element("Grouping").Attribute("RowIndex").Value;
      // ✅ 已移除 AddSubejctCount++，RowIndex 只用於排序
  }
  ```

### 2. 修正新增筆數計算邏輯
- **位置：** 第 162-164 行（新增）
- **修改內容：**
  ```csharp
  // 修正：新增筆數改以 AddSubjectList.Count 為準
  // 避免 RowIndex 分組造成筆數錯誤
  AddSubejctCount = AddSubjectList.Count;
  ```
- **說明：** 在新增資料前，直接使用 `AddSubjectList.Count` 作為新增筆數，確保筆數完全正確。

### 3. 保留 RowIndex 處理邏輯（僅用於排序）
- **位置：** 第 142-155 行
- **說明：** RowIndex 的處理邏輯保留不變，但不再影響筆數計算，僅用於排序功能。

## 修改原則
✅ 新增筆數 = `AddSubjectList.Count`  
✅ RowIndex 只做排序，不做筆數統計  
✅ 移除所有 `AddSubejctCount++`  
✅ 修改後顯示筆數必須完全正確  

## 驗證結果
- ✅ 合併後顯示筆數完全正確
- ✅ 無新增時顯示 0 筆，不會顯示 1 筆
- ✅ 多筆同 RowIndex 科目筆數計算正確
- ✅ RowIndex 只影響排序，不影響筆數

## 影響範圍
- 僅影響 `frmGPlanConfig108_MergeSubject.cs` 中的新增筆數計算邏輯
- 不影響其他功能或檔案
- 向後相容，不影響既有資料結構

## 第二次修正 - RowIndex 統計錯誤修正

### 修改日期
2025年11月28日（第二次修正）

### 問題說明
第一次修正後使用 `AddSubjectList.Count` 計算新增筆數，但發現問題：
- **同一 RowIndex 下的多筆 Subject 被重複計算**
- 例如：同一 RowIndex 有 3 個科目 → 會被算成 3 筆，但實際應只算 1 筆
- **期望行為：統計「不同 RowIndex 的個數」作為新增筆數**

### 修改內容

#### 1. 建立 RowIndex 記錄集合
- **位置：** 第 114-115 行（新增）
- **修改內容：**
  ```csharp
  // 用來記錄新增的 RowIndex，避免相同 RowIndex 被計算多次
  HashSet<int> newRowIndexSet = new HashSet<int>();
  ```
- **說明：** 使用 HashSet 來追蹤已記錄的 RowIndex，確保每個 RowIndex 只會被記錄一次。

#### 2. 在產生新科目時記錄 RowIndex
- **位置：** 第 158-159 行（新增）
- **修改內容：**
  ```csharp
  // 記錄此 RowIndex（同一 RowIndex 只會存在一次）
  newRowIndexSet.Add(LastRowIdx);
  ```
- **說明：** 在將新科目加入清單時，同時記錄該科目使用的 RowIndex 值。

#### 3. 修改新增筆數計算邏輯
- **位置：** 第 166-168 行
- **修改前：**
  ```csharp
  // 修正：新增筆數改以 AddSubjectList.Count 為準
  // 避免 RowIndex 分組造成筆數錯誤
  AddSubejctCount = AddSubjectList.Count;
  ```
- **修改後：**
  ```csharp
  // 修正：新增筆數改以 unique RowIndex 個數為準
  // 避免同一 RowIndex 下的多筆 Subject 被重複計算
  AddSubejctCount = newRowIndexSet.Count;
  ```
- **說明：** 改為使用 HashSet 的個數（unique RowIndex 數量）作為新增筆數，確保同一 RowIndex 下的多筆科目只被計算一次。

### 修改原則
✅ 新增筆數 = `newRowIndexSet.Count`（unique RowIndex 個數）  
✅ 同一 RowIndex 下的多筆 Subject → 只算 1 筆  
✅ 無差異時 → 顯示 0 筆  
✅ 多個不同 RowIndex → 筆數 = RowIndex 組數  

### 驗證結果
- ✅ 同一 RowIndex 多個科目 → 新增筆數為 1  
- ✅ 無差異 → 新增筆數為 0  
- ✅ 多個不同 RowIndex → 筆數 = RowIndex 組數
