## 2. `moe_group_code -> name` 索引做法

`DataAccess.GetMoeGroupCodeNameDict()` 一次查詢：

```sql
SELECT id, moe_group_code, name
FROM graduation_plan
WHERE moe_group_code IS NOT NULL
  AND TRIM(moe_group_code) <> ''
ORDER BY id DESC;
```

建立 `Dictionary<string, string>`：Key = `moe_group_code`（Trim）、Value = `name`。重複代碼只保留 `id` 最大的一筆，避免 duplicate key。

`frmCreateGPlanMain108` 的 BackgroundWorker 讀取清單後呼叫一次，再傳入各份課規的 `ParseSourceGPlan`。不可對每個 Subject 重查 DB。

## 3. Subject 課程代碼前 16 碼比對規則

執行順序：

```text
ParseMOEXml()
  → ParseRefGPContentXml()
  → ParseSourceGPlan(index)
  → SetCheckSubjectLevel(...)
  → CheckData()
```

`ParseSourceGPlan` 走訪 `RefGPContentXml` 的每個 `Subject`：

- 無 `課程代碼`、空白、長度 &lt; 16：略過該筆，不拋錯。
- 正常：`subjectGroupCode = 課程代碼.Substring(0, 16)`，與目前 `GDCCode` 比較。

`RefGPContentXml`、`GDCCode`、索引為 null／empty 時直接結束。

## 4. `來源課規` 新增／修正／移除條件

| 情況 | 行為 |
| --- | --- |
| 前 16 碼 == 目前 `GDCCode`，且已有 `來源課規` | 移除 Attribute |
| 前 16 碼 == 目前 `GDCCode`，且本來就沒有 | 不變 |
| 前 16 碼 != 目前 `GDCCode`，索引找得到 | 設成來源課規 `name`（不是代碼）；值已正確則不變 |
| 前 16 碼 != 目前 `GDCCode`，索引找不到 | 不猜名稱、不新建錯誤屬性、不覆蓋既有值、不 MessageBox |

只改記憶體 XML，不寫 DB。

## 5. `needUpdateSourceGPlan` 用途

僅在實際新增、修正或移除 `來源課規` 時設為 `true`。值本來就正確則維持 `false`。

主畫面狀態：

```csharp
if (data.needUpdateSourceGPlan)
{
    data.Status = "更新";
}
```

`ParseStatus()` 在既有差異數為 0 時，若此旗標為 true，也把狀態從「無變動」改成「更新」。不新增新的 Status 類型。

目的：來源 Subject 會被 `HasSourceGPlan()` 設成「略過」，整份課規仍可因 Attribute 異動進入 UPDATE。

## 6. 為何來源 Subject 維持 `ProcessStatus = 略過`

從其他課程規劃表合併進來的 Subject 不應被目前課程代碼總表判成更新或刪除。`CheckData()` 仍用既有 `HasSourceGPlan()`：任一同代碼 Subject 有非空白 `來源課規` → `ProcessStatus = "略過"`。本次未改該 helper 的用途。

## 7. 為何重新讀取／設定畫面不直接寫 DB

比對、設定畫面 Load、設定畫面 Save／OK 都只改記憶體。使用者可能只查看來源課規後關閉。正式寫入仍只走主畫面「產生／建立」。

## 8. 主畫面「產生」如何回寫 `graduation_plan.content`

既有 `btnCreate_Click`：`ProcessStatus = "略過"` 時加入 `subj.GPlanXml`（與 `RefGPContentXml` 同一批 XElement）。`ParseSourceGPlan` 改的 Attribute 會跟著組回最終 XML。不改用 `MOEXml` 組略過科目，以免遺失來源課規與既有設定。

只有此處 `UPDATE graduation_plan SET content = ...`。

## 9. `frmCreateGPlanItemSetup108` 新增「來源課規」欄位

- 位置：科目名稱之後、校訂部定之前
- `Name` / `HeaderText` = 來源課規
- `ReadOnly = true`，`Width = 180`
- Load 時從 `subj.GPlanXml` 讀 Attribute；有值顯示、無值空白；同科目多筆相同來源只顯示一次，不同來源去重後以逗號連接
- UI 不查 DB、不重判來源

## 11. 實作中發現的例外資料或風險

- `moe_group_code` 重複時只留最新 `id`，舊同代碼課規名稱不會進索引。
- 課程代碼短於 16、缺 Attribute、XML 壞掉：單筆 catch，不中斷整份課規。
- 索引查不到時保留原 `來源課規`；若原值本身錯誤也無法自動修正。
- `GPlanDict` / `chkSubjectInfo.GPlanXml` 與 `RefGPContentXml` 共用同一 XElement，Attribute 變更會帶到產生與設定畫面。
- 綜合高中 `M111960` 與既有合併一年級邏輯未改；來源課規比對在 `CheckData()` 之前，合併進來的一年級科目若已在 XML 內會一併比對。
- `frmCreateGPlanMainBatch` 未改（本 Todo 範圍僅 108 主畫面產生流程）。
